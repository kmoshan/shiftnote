# ShiftNote 架构说明

## 1. 分层结构

```
┌──────────────────────────────────────────────────────────────┐
│  Vue 3 视图层（WebView2 内运行）                              │
│  views/ + components/                                        │
│    · 只负责渲染与交互，不直接拼 SQL                           │
├──────────────────────────────────────────────────────────────┤
│  状态层 Pinia（stores/）                                      │
│    tasks   · 列表 / 详情 / 筛选 / 写操作编排                   │
│    ui      · 主题、编辑器开关                                  │
│    confirm · Promise 化二次确认                                │
│    toast   · 操作反馈                                          │
├──────────────────────────────────────────────────────────────┤
│  服务层 services/api.ts                                       │
│    · 对 @tauri-apps/api 的 invoke 做类型化封装                 │
│    · 把后端 AppError 统一成 ApiFailure（含 message / code）    │
├──────────────────────────────────────────────────────────────┤
│  IPC 边界（Tauri Command，仅接受结构化参数）                   │
├──────────────────────────────────────────────────────────────┤
│  Rust 命令层 commands/                                        │
│    app.rs      · 版本、数据目录、备份                          │
│    tasks.rs    · 事项 + 进展的全部命令                         │
│    settings.rs · 键值配置                                      │
│    · 只做参数编排，不含 SQL                                    │
├──────────────────────────────────────────────────────────────┤
│  仓储层 db/                                                   │
│    tasks.rs    · 事项查询/写入、视图过滤、搜索                  │
│    updates.rs  · 进展追加与编辑（保留历史）                     │
│    settings.rs · 配置读写                                      │
│    migrations.rs · 版本化迁移                                  │
│    mod.rs      · 连接、PRAGMA、损坏自愈、备份                   │
├──────────────────────────────────────────────────────────────┤
│  SQLite（本地文件，WAL 模式，外键开启）                        │
└──────────────────────────────────────────────────────────────┘
```

## 2. 关键设计决策

### 2.1 时间

- 所有时间列统一存 **Unix 毫秒时间戳（UTC，INTEGER）**。
- 计算“今天/昨天”这类边界时在 Rust 侧用 `chrono::Local` 求出本地零点，再转成毫秒；
  避免前端时区与数据库时区不一致。
- 前端只做展示格式化（`services/format.ts`），不参与时间计算。

### 2.2 搜索

- 采用 `LIKE ... ESCAPE '\'` 同时匹配：标题、描述、负责部门，
  以及子查询 `task_updates.content`。
- 用户输入中的 `% _ \` 会被转义，避免通配符注入。
- 全局搜索视图（`view=search`）只排除回收站，**包含已完成与已隐藏事项**，
  满足“已归档内容仍可检索”的要求。
- 个人/部门级数据量（数千条）下 `LIKE` 足够；若未来数据量增大，可平滑切换到 FTS5，
  届时只需替换 `db/tasks.rs` 中的搜索子句。

### 2.2.1 日期口径

- 事项的日期筛选与「今日事项」都基于 `COALESCE(recorded_at, created_at)`：
  用户可手工指定记录时间，缺省则为创建时间。
- 日期范围以半开区间 `[当天 00:00, 次日 00:00)` 传入（前端按本地时区计算边界），
  避免“当天 23:59:59.999 之后才算”的边界误差。

### 2.3 进展记录不可覆盖

- `task_updates` 只做 INSERT；编辑走 `UPDATE content, updated_at, edited_at`，
  `created_at` 永不修改。
- 每条进展写入时同步 `tasks.updated_at`，使“最近更新”反映最新处理时间。
- 删除单条进展需要二次确认；删除事项时通过外键 `ON DELETE CASCADE` 级联清理。

### 2.4 完成 / 隐藏 / 删除的语义

| 操作 | 数据变化 | 提醒 | 可搜索 | 可恢复 |
| --- | --- | --- | --- | --- |
| 完成 | `status='done'`, `completed_at` | 立即关闭 | 是 | 取消完成 |
| 隐藏 | `hidden=1` | 立即关闭 | 是（全局搜索） | 取消隐藏 |
| 移入回收站 | `deleted_at=now` | 立即关闭 | 否 | 从回收站恢复 |
| 永久删除 | DELETE + 级联 | 记录消失 | 否 | 不可恢复 |

完成与隐藏都不会丢失任何进展记录。

### 2.5 并发与一致性

- 单用户桌面场景，采用 `Mutex<Connection>` 串行化访问，避免 SQLite 写锁竞争。
- 多语句写操作使用 `unchecked_transaction()` 包裹（事项创建、状态切换、进展追加、
  永久删除），保证原子性。
- WAL 模式 + `synchronous=NORMAL` + `busy_timeout=5000`，兼顾吞吐与安全。

### 2.6 数据库损坏自愈

启动时：

1. `PRAGMA quick_check(1)` 自检；
2. 打开/迁移失败且文件存在时，把原文件重命名为
   `shiftnote.corrupt-<时间戳>.db`；
3. 清理残留 `-wal` / `-shm`；
4. 重建空库并继续启动，同时在设置页与顶部提示中告知用户备份路径。

这样避免“文件损坏导致软件彻底打不开”，也保留了取证/恢复的可能。
只有**确认为损坏**（`DatabaseCorrupt` / `NotADatabase` / 自检失败）才会重建；
被占用、无权限等错误直接上抛，避免误伤正常数据库。

### 2.7 备份恢复

- 通过 SQLite 在线备份 API 把备份文件的页面复制进**当前连接**，无需重启应用，
  也就绕开了“文件被占用无法替换”的问题。
- 覆盖前先对当前库做一次快照（`backups/pre-restore-*.db`）；迁移或外键校验失败时
  自动用快照回滚，保证不会留下半截数据。
- 恢复后前端重新加载列表、主题与统计信息。

## 3. 模块职责边界

- **组件不调用 `invoke`**：所有 IPC 调用只出现在 `services/api.ts`。
- **命令层不含 SQL**：命令只做参数搬运与事务编排。
- **仓储层不感知 Tauri**：`db/*.rs` 只依赖 `rusqlite`，因此可以用内存库做单元测试。
- **错误统一**：`AppError` 序列化为 `{ code, message }`，前端 `ApiFailure` 统一消费。
