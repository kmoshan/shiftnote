# ShiftNote 架构说明

## 1. 分层结构

## 2. 关键设计决策

### 2.1 时间

- 所有时间列统一存 **Unix 毫秒时间戳（UTC，INTEGER）**。
- 计算“今天/昨天”这类边界时在 Rust 侧用 `chrono::Local` 求出本地零点，再转成毫秒；
  避免前端时区与数据库时区不一致。
- 自定义记录日期与交接班次在前端按本地时间转换为 UTC 毫秒；Rust 端验证半开区间。
- 导出时间明确标注 UTC，避免目标电脑时区变化造成歧义。

### 2.2 搜索

- 采用 `LIKE ... ESCAPE '\'` 同时匹配：标题、描述、负责部门，
  以及子查询 `task_updates.content`。
- 用户输入中的 `% _ \` 会被转义，避免通配符注入。
- 全局搜索视图（`view=search`）排除回收站与归档，包含已完成与已隐藏事项。
- 今日视图搜索固定当天，忽略其他视图保存的自定义日期。
- 个人/部门级数据量（数千条）下 `LIKE` 足够；若未来数据量增大，可平滑切换到 FTS5，
  届时只需替换 `db/tasks.rs` 中的搜索子句。

### 2.2.1 日期口径

- 事项的日期筛选与「今日事项」都基于 `COALESCE(recorded_at, created_at)`：
  用户可手工指定记录时间，缺省则为创建时间。
- 日期范围以半开区间 `[当天 00:00, 次日 00:00)` 传入（前端按本地时区计算边界），
  避免“当天 23:59:59.999 之后才算”的边界误差。

### 2.3 进展记录不可覆盖

- `task_updates` 只做 INSERT；编辑走 `UPDATE content, updated_at, edited_at`，
  `created_at` 永不修改。
- 每条进展写入时同步 `tasks.updated_at`，使“最近更新”反映最新处理时间。
- 删除单条进展需要二次确认；删除事项时通过外键 `ON DELETE CASCADE` 级联清理。

### 2.4 完成 / 隐藏 / 删除的语义

| 操作 | 数据变化 | 提醒 | 可搜索 | 可恢复 |
| --- | --- | --- | --- | --- |
| 完成 | `status='done'`, `completed_at` | 立即关闭 | 是 | 取消完成 |
| 隐藏 | `hidden=1` | 立即关闭 | 是（全局搜索） | 取消隐藏 |
| 归档 | 仅 done 可设 `archived=1` | 立即关闭 | 常规搜索排除 | 取消归档；取消完成自动取消归档 |
| 移入回收站 | `deleted_at=now` | 立即关闭 | 否 | 从回收站恢复 |
| 永久删除 | DELETE + 级联 | 记录消失 | 否 | 不可恢复 |

完成与隐藏都不会丢失任何进展记录。

### 2.5 并发与一致性

- 单用户桌面场景，采用 `Mutex<Connection>` 串行化访问，避免 SQLite 写锁竞争。
- 多语句写操作使用 `unchecked_transaction()` 包裹（事项创建、状态切换、进展追加、
  永久删除），保证原子性。
- 生产连接使用内存 SQLite，`journal_mode=MEMORY`、`temp_store=MEMORY`，不生成明文 WAL 或恢复暂存文件。
- `fs2` 文件锁在 `Db` 生命周期内独占数据目录对应的锁文件，防止新版本实例同时写同一加密数据库。
- 写操作在连接锁内完成校验与加密保存，再向调用方报告成功；保存失败重载上次成功的密文镜像，重载失败则锁定会话。闭包返回错误时也不保留其中的局部写入。
- 批量接受去重后的明确 IDs 与目标 action，最多 1,000 项；预检失败整批拒绝，单事务包含提醒停止规则。
- 前端列表、详情、历史和交接读取各有请求版本，旧成功、失败和 loading 不覆盖当前状态。
- 列表分页总数和条目复用同一过滤条件，排序追加唯一 ID；手动移动在完整视图中解析相邻锚点。

### 2.6 口令解锁与静态加密

- 生产启动仅创建锁定的内存连接；业务 IPC 在后端再次检查解锁状态，前端解锁页不能替代后端门禁。
- `shiftnote.db` 保留原路径名，但内容改为版本化认证加密封装，不能直接用 SQLite 工具打开。口令经 Argon2id 派生 256 位密钥，AES-256-GCM 加密数据库镜像并认证完整头部；每次保存生成新的随机 nonce。
- 格式 v1 固定 Argon2id v1.3、64 MiB、3 次迭代、1 个 lane；文件不能指定任意 KDF 参数。会话密钥、KDF 工作区和命令接收的口令使用清零容器，密码库启用相应清零功能。
- 仅在口令验证、结构预检与完整性检查成功后迁移并载入内存。错口令、损坏或不支持的文件不触发自动重建，也不覆盖原文件。
- 首次发现旧版明文 `.db` 时，需要用户设置并确认口令、明确同意迁移。旧备份单独由设置页「加密旧备份」处理；失败的来源保留，不能把主库迁移视为全部历史副本已加密。
- 静态加密保护关闭后的数据库及加密备份。解锁后的进程内存、操作系统分页文件和崩溃转储不在此保护范围内；不提供忘记口令后的找回功能。

### 2.7 备份恢复

- 新备份为 `.snbak` 认证加密文件，可复制到其他电脑。跨安装或其他 vault 的备份使用生成备份时的原口令解密，即使新 vault 选择了相同口令也需明确输入。
- `.snbak` 先认证解密到内存；兼容的旧 `.db` 以只读方式复制到内存。来源必须通过结构白名单、版本、完整性、外键、索引、核心查询与交接 JSON 检查，然后才在内存暂存库迁移。
- 生产边界为数据库镜像 128 MiB、每表 10 万行、总计 50 万行、单值 8 MiB；交接快照和 JSON 还有独立限额。每个 SQL 校验阶段限制 1 亿 VM 步和 30 秒，页面复制另有 30 秒预算；这些不是整次操作的总耗时保证。
- 当前连接锁贯穿恢复流程。覆盖前生成加密 `pre-restore-*.snbak`；新库密文原子保存成功后才交换内存连接，失败不替换当前会话。恢复暂存库和校验副本仅存在于内存。
- 恢复后前端使旧请求、草稿和缓存失效，再加载列表、主题与统计信息。

### 2.8 交接快照与导出

- 草稿引用实时事项，保存时保留副本；定稿事务冻结完整事项与选定进展，实时引用删除设 NULL。
- 已定稿内容不接受编辑或删除，需要调整时复制为新草稿；来源已不存在时明确拒绝复制。
- 预览与 Markdown/TXT 使用 `export.rs` 同一生成器。Rust 先写同目录临时文件并同步，再原子发布；覆盖需用户确认。
- Markdown/TXT 用于分享，仍是明文文件，导出界面明确提示；它们不属于 `.snbak` 加密备份。

## 3. 模块职责边界

- **组件不调用 `invoke`**：所有 IPC 调用只出现在 `services/api.ts`。
- **命令层不含 SQL**：命令只做参数搬运与事务编排。
- **仓储层不感知 Tauri**：SQL、内存连接、加密持久化与资源检查可脱离 WebView 做单元测试。
- **错误统一**：`AppError` 序列化为 `{ code, message, invalidIds? }`；批量校验包含失效 IDs，文件已存在用 conflict 码。

以上为当前实现的职责与失败处理约定，验证结果以 `TESTING.md` 记录为准；架构说明不代表所有测试或原生交互验收均已通过。
